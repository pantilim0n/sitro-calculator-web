# Приём заявок с сайта СИТРО

## Выбранная схема

Платная версия Яндекс 360 и интерфейс Яндекс Форм не используются.

1. Заказчик выбирает STL в калькуляторе, получает расчёт и заполняет имя, телефон и комментарий.
2. Сайт получает временную ссылку для загрузки.
3. Браузер заказчика загружает модель напрямую в отдельную папку приложения на Яндекс Диске, поэтому файл не проходит через ограничение размера Vercel Functions.
4. Сайт показывает подтверждение отправки и остаётся на странице СИТРО.
5. Менеджеру приходит служебное уведомление в Telegram со ссылками на модели. Заказчику Telegram не нужен.
6. Telegram, MAX, телефон и почта остаются дополнительными способами связи в разделе контактов.

Файлы сохраняются в каталоге приложения `Заявки/ГГГГ-ММ-ДД/НОМЕР-ЗАЯВКИ` на Яндекс Диске. OAuth-приложение получает доступ только к своей папке и не видит остальные файлы владельца.

## Закрытые настройки сервера

В Vercel нужны три переменные окружения:

- `YANDEX_DISK_TOKEN` — OAuth-токен с единственным правом `cloud_api:disk.app_folder`;
- `TELEGRAM_BOT_TOKEN` — новый токен бота `@sitrosupportbot`;
- `TELEGRAM_CHAT_ID` — идентификатор чата владельца.

Значения нельзя сохранять в Git, документах проекта или переписке. Их вводят непосредственно в настройках Vercel, а после переноса сайта — в закрытых настройках российского сервера.

## Ограничения

- не более 10 файлов в одной заявке;
- STL или 3MF;
- не более 50 МБ на один файл;
- для расчёта в текущем калькуляторе выбирается STL; поддержка расчёта 3MF требует отдельного парсера.

## Перед включением

1. Перевыпустить токен Telegram-бота через BotFather.
2. Создать OAuth-приложение Яндекса с правами Яндекс Диска.
3. Добавить три переменные в Vercel для Production.
4. Выполнить тестовую заявку с небольшим STL.
5. Проверить папку на Яндекс Диске и сообщение в Telegram.
