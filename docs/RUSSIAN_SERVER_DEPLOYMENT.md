# СИТРО на российском сервере

Обновлено: 5 октября 2026 года.

## Рабочая схема

Сайт работает на российском VPS `178.250.159.212` в двух контейнерах:

- `app` — сайт, калькулятор, админка и серверные обработчики;
- `caddy` — HTTPS и передача запросов приложению.

Основной адрес: `https://ситро-3д.рф`.
Резервный адрес при старом DNS-кэше: `https://www.ситро-3д.рф`.

## Постоянные данные

Docker-том `order_data` подключён к `/data` и содержит:

- `/data/orders` — заявки и модели STL/3MF;
- `/data/site` — тарифы, материалы, услуги, контакты, отзывы, пароль и фотографии, изменённые через админку.

Сначала сервер ищет актуальные данные в `/data/site`, затем использует файлы из установленной версии сайта. Поэтому изменение в админке видно сразу и сохраняется после пересборки контейнера.

GitHub хранит код и резервную историю изменений. Недоступность GitHub не мешает уже опубликованному сайту принимать заявки и сохранять правки в админке. Если резервное сохранение в GitHub не удалось, админка применяет изменение на сайте и сообщает об ошибке резервной синхронизации.

## Уведомления

- MAX отправляется напрямую с российского сервера.
- Telegram API недоступен из сети VPS, поэтому текст уведомления шифруется AES-256-GCM и передаётся в закрытый запуск GitHub Actions. Токен Telegram и ключ расшифровки хранятся в GitHub Secrets.
- Заявка записывается на диск до уведомлений. Сбой Telegram, MAX или GitHub не удаляет её; повторную отправку можно запустить из админки.

## Обновление кода

```sh
git pull --ff-only
docker compose up -d --build
```

Перед публикацией выполняются автоматические тесты. После обновления проверяются `/healthz`, главная страница, калькулятор и админка.

## Резервные копии

Таймер `sitro-backup.timer` ежедневно в 03:30 по Москве запускает `deploy/backup-orders.sh`.

Архив содержит весь постоянный том `/data` и закрытый `.env.server`. Для архива создаётся SHA-256 контрольная сумма. Права доступа — только `root`, срок хранения — 30 дней.

Периодически нужно копировать свежий архив на другой компьютер или отдельное хранилище. Локальная контрольная копия уже создана в каталоге `SITRO-backups` на Mac.

## Восстановление

1. Развернуть чистый сервер с Docker.
2. Клонировать репозиторий в `/opt/sitro/app`.
3. Восстановить `.env.server` из защищённого архива.
4. Восстановить содержимое `/data` в том `app_order_data`.
5. Запустить `docker compose up -d --build`.
6. Проверить сайт, админку и контрольную заявку.

## Защита сервера

- UFW разрешает только SSH, HTTP и HTTPS, необходимые для управления и сайта.
- Автоматические обновления безопасности включены.
- Fail2ban следит за входом SSH: пять неудачных попыток за десять минут блокируют адрес на один час.
- Воспроизводимая конфигурация находится в `deploy/fail2ban-sitro-sshd.conf` и устанавливается в `/etc/fail2ban/jail.d/sitro-sshd.conf`.
- HTTPS-сертификат выпускает и автоматически продлевает Caddy.

Парольный вход SSH пока сохранён для совместимости с панелью хостинга. После создания отдельной аварийной учётной записи можно перейти только на SSH-ключи.
