# Перенос СИТРО на российский сервер

## Подготовленный вариант

Проект запускается на обычном российском VPS в двух контейнерах:

- `app` — сайт, калькулятор, админка и серверные обработчики;
- `caddy` — HTTPS, перенаправление `www` и передача запросов приложению.

Основной сайт, калькулятор, заявки, админка и MakerWorld работают на российском VPS. Vercel оставлен включённым как временная резервная площадка на период проверки после переноса.

Модели заказчиков и записи заявок сохраняются в отдельном постоянном Docker-томе `order_data` на VPS. Это исключает зависимость рабочего приёма заказов от доступности Яндекс Диска из российского дата-центра. Ссылки на модели подписаны серверным секретом и имеют ограниченный срок действия.

Если конкретный провайдер или локальный прокси ещё держит старый адрес Vercel, сервер доступен для диагностики по `https://sita4816.fvds.ru`. Этот адрес закрыт от индексации и не заменяет основной домен.

## Требования к серверу

- Ubuntu 24.04 LTS;
- российский IPv4-адрес;
- минимум 1 ядро, 1 ГБ памяти и 10 ГБ диска;
- открытые входящие порты 22, 80 и 443;
- Docker Engine с Compose.

## Что потребуется при установке

1. IP-адрес сервера и доступ SSH администратора.
2. Доступ к DNS домена `ситро-3д.рф` в REG.RU.
3. Закрытые переменные из `.env.server.example`. Их нельзя добавлять в GitHub или сообщения.
4. Возможность исходящих HTTPS-соединений к GitHub, Яндекс Диску, Telegram, MAX и MakerWorld.

## Порядок переноса

1. Установить Docker и скопировать репозиторий на сервер.
2. Создать `.env.server` только на сервере и заполнить секреты.
3. Запустить `docker compose up -d --build`.
4. До переключения домена проверить контейнер напрямую через временное имя или локальную подмену DNS.
5. Проверить главную страницу, калькулятор, админку, MakerWorld и загрузку STL/3MF.
6. Отправить контрольные заявки обоих типов и убедиться, что они появились в админке, Telegram и MAX.
7. Заменить A-записи корневого домена и `www` на российский IP.
8. Дождаться выпуска HTTPS-сертификата и повторить проверки на `https://ситро-3д.рф`.
9. Оставить Vercel включённым минимум на семь дней как возможность быстрого возврата.

## Обновление сайта после переноса

На первом этапе GitHub остаётся источником кода и данных админки. На сервере обновление выполняется так:

```sh
git pull --ff-only
docker compose up -d --build
```

Заявки и файлы продолжают храниться на Яндекс Диске. Следующий этап независимости — перенести данные админки из GitHub в локальную базу с ежедневной резервной копией.

## Резервная копия

Команда `./scripts/backup-project.sh` создаёт:

- полный Git bundle со всей историей;
- архив рабочих файлов без секретов;
- отдельную папку с датой и временем создания.

Секретный файл `.env.server` в архив не попадает. Его резервная копия должна храниться отдельно в защищённом месте.
